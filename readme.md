# NetSpeak

Простой голосовой и текстовый чат для локальной сети. Без интернета,
без регистрации, без установки чего-либо на чужие компьютеры.

Один человек запускает сервер у себя, остальные подключаются по адресу —
и оказываются в одном канале, где слышно друг друга.

---

## Что это

- **Голос.** До 8 человек одновременно, все слышат всех. Связь напрямую между
  браузерами (WebRTC), без сторонних серверов.
- **Чат.** Каналы, личные сообщения, файлы до 32 МБ.
- **Переносное.** Два файла `.exe`. Копируете куда угодно, запускаете —
  Python устанавливать не нужно.
- **Без интернета.** Никаких STUN/TURN, никаких облаков. Только ваша сеть.

---

## Два файла

| Файл | Для чего |
|---|---|
| **NetSpeakServer.exe** | Сервер. Запускается на том компьютере, который собирает остальных. |
| **NetSpeak.exe** | Клиент. Подключается к серверу по адресу. |

Разделено намеренно: сервер живёт долго, им нужно управлять — остановить
или перезапустить, — и он всегда на виду. Клиент открывают на минуту.

Положите **оба** файла в одну папку и запустите `NetSpeakServer.exe`.
Клиент можно скопировать только тем, кому нужно.

---

## Как пользоваться

**На своём компьютере (там, где сервер):**

1. Запустите `NetSpeakServer.exe`.
2. Окно «Локальный сервер» покажет адрес, по которому подключаться, и живой
   журнал. Оно всегда видно, пока сервер работает.
3. Там же — кнопки **Перезапустить** и **Остановить**. После остановки кнопка
   превращается в «Запустить снова», а точка в строке состояния гаснет.
4. Закрыли окно — сервер остановился. Незачем оставлять его висеть, если
   управлять им уже некому.

Если сервер вдруг перестал работать — компьютер заснул, сеть мигнула, кто-то
прибил процесс, — окно это заметит и поднимет сервер заново само. Проверяется
и процесс, и то, что сервер **отвечает**: после сна сокет часто остаётся
живым, но новые соединения уже не принимает, и по одному процессу это не
видно.

В журнале появится строка — «сервер молча завершился, поднимаю заново» либо
«сервер жив, но не отвечает — перезапускаю». Если падает подряд несколько
раз, программа прекращает попытки и пишет об этом: значит дело не в случайности
и пора разбираться. Ничего нажимать не нужно.

При нажатии **Остановить** сервер не поднимается — это осознанное решение
пользователя, сторож его не трогает. То же, если на порту уже отвечает чужой
сервер: свой мы тогда не поднимаем, чтобы не мешать.

**На остальных компьютерах:**

1. Запустите `NetSpeak.exe`.
2. Впишите адрес и порт (прошлый подставляется сам).
3. Имя и аватар спросят один раз. Дальше приложение заходит сразу, в канал
   «Общий», без всяких вопросов.

Можно и наоборот: запустить `NetSpeak.exe` у себя и в поле адреса вписать
адрес чужого сервера.

Окно подключения после успеха просто прячется — остаётся только окно
приложения. Оно закрывается с вопросом «Вы уверены, что хотите закрыть?»,
и вместе с ним закрывается всё.

## Рабочие файлы

Обе программы используют папку, в которой лежат. При первом запуске рядом
появляется:

```
папка с exe
├── settings/     настройки программы
│   ├── app.json
│   ├── server.json    состояние обновлений сервера
│   └── update.json    состояние обновлений клиента
├── user/         ваш профиль
│   ├── profile.json
│   └── avatars/  картинки профиля
├── history/      переписка по каналам (старый формат, перенесён в базу)
│   ├── general.jsonl
│   └── work.jsonl
├── logs/         журналы
│   ├── server.log
│   └── launcher.log
├── update/       скачанное обновление, пока не установлено
└── data/         служебное
    ├── cert.pem  ключ и сертификат
    ├── netspeak.db   база: люди и переписка
    ├── files/    загруженные файлы
    ├── webview-client/  хранилище окна клиента
    └── webview-server/  хранилище окна сервера
```

Папку `user/` можно переносить между компьютерами: скопировали — получили
себя на другой машине. `settings/` привязан к железу, его переносить незачем.
`history/` тоже переносится — это и есть переписка, её жалко терять.

> Обновляете exe — **кладите обновлённые файлы в ту же папку**. Настройки
> лежат рядом с exe, поэтому новый файл, запущенный из другой папки, их
> не увидит. Путь всегда показан в окне подключения: «Рабочие файлы: …».

## История переписки

Сервер помнит, что было сказано. Переписка лежит в `history/`, по файлу на
канал: `history/general.jsonl`, `history/work.jsonl` — по строке на сообщение.

Человек заходит в канал и видит, что там было до него. Не всё подряд, а
только этот канал: кто в «Общем», того в «Работе» не видно.

Файлы обычный текст, по одному JSON-объекту в строке. Открываются блокнотом,
и их можно подложить на другой сервер.

Подробности, из-за которых так:

- **Дописываем, а не переписываем.** Если в разгар беседы выключат питание,
  уже написанное останется целым.
- **Держим 2000 сообщений на канал.** Старое подрезается при запуске сервера,
  файлы не растут бесконечно.
- **Переносится вместе с папкой.** Скопировали `history/` на другой компьютер —
  переписка переехала.

Свою переписку можно стереть: удалите папку `history/`.

### Как узнают человека

У каждого два идентификатора, и это не одно и то же:

| | Что это | Живёт |
|---|---|---|
| **uid** | сам человек | переживает перезапуск программы |
| **sid** | конкретное соединение с сервером | живёт, пока открыто окно |

Раньше был только `sid`, и из-за этого после перезапуска клиента вся
прошлая переписка вдруг оказывалась «чужой»: сообщения выравнивались
влево и теряли аватар. Теперь у сообщения лежит и `uid`, и по нему
приложение понимает, что это написали вы.

`uid` — случайные 16 шестнадцатеричных цифр, он хранится в
`localStorage`, то есть в профиле браузера или в
`data/webview-client/`, если открыто своё окно. Поэтому он ещё и
переезжает вместе с программой на другой компьютер.

Из `uid` считается цвет кружка. Раньше цвет брался из `sid`, а встроенный
`hash()` для строк меняется при каждом запуске процесса — человек
менял бы цвет после каждой перезагрузки сервера. Теперь цвет
стабильный.

> У разных людей `uid` разный: он хранится у каждого в своём браузере,
> а не на сервере. Поэтому на одном сервере может спокойно сидеть
> несколько человек, и никто не станет «вы».

Если хотите начать с чистого листа — удалите папку
`data/webview-client/`, и программа выдаст новый `uid`.

## Как узнаётся человек

У каждого человека есть постоянный номер — `uid`. По нему программа
отличает «свои» сообщения от чужих, помнит имя с аватаром и понимает, кто
вернулся в сети.

Номер выводится из двух вещей:

| Часть | Откуда | Зачем |
|---|---|---|
| номер компьютера | реестр Windows (MachineGuid) | тот же ноутбук под другим углом — тот же человек |
| зёрныше программы | `user/device.json` | две копии на одном компьютере — разные люди |

**Поэтому перенести папку на другой компьютер — получить другого
человека.** Раньше номер лежал в хранилище браузера, и стоило перенести
папку — как человек становился тем же самым: с тем же именем и тем же
аватаром, а на сервере двое показывались одинаково.

Заодно номер **переживает потерю настроек браузера**: считается из
устройства, а не из того, что помнит браузер. Почистили кэш — номер тот
же, и сервер вернул прежнее имя с аватаром из базы.

Если страницу открыли с телефона или чужого ноутбура (не приложением, а
просто ссылкой), номера устройства у браузера нет и взять его неоткуда —
тогда номер живёт в самом браузере, как и раньше.

### Своё имя и чужое имя

Имя и аватар хранятся в двух местах, и они не спорят:

* `user/profile.json` — мои настройки **на этом компьютере**;
* таблица `users` в базе — кто бывал на сервере.

Правило: **свою строку человек перезаписывает сам, чужие строки не трогает
никто.** Переименовались с ноутбука — у ноутбука своё имя, у хозяина
сервера своё.

Раньше это было не так: клиент брал имя и аватар прямо из файла на сервере,
и подключившийся с ноутбука получал имя того, кто сервер запустил.

## Если не слышно

Голос идёт **напрямую между компьютерами**, минуя сервер: браузер
соединяется с собеседником сам. Сервер только передаёт приглашение.

Поэтому главная причина «вроде подключились, а звука нет» — **брандмауэр
Windows**: он не пускает входящие пакеты, и связи не возникает совсем.

**Что делать:**

1. Нажмите в окне сервера **«Разрешить в брандмауэре»**. Если прав
   администратора нет — закройте программу, запустите `NetSpeakServer.exe`
   правой кнопкой → «Запуск от имени администратора».
2. Либо разрешите оба файла вручную: «Брандмауэр Windows → Правила для
   входящих подключений» — для `NetSpeak.exe` и `NetSpeakServer.exe`,
   программы и частные сети.

О том же сервер пишет в журнал при запуске — строка «брандмауэр НЕ пускает
входящие» в logs/launcher.log означает, что звука не будет, пока правило
не добавлено.

**Как понять, что дело в этом:** над чатом появляется полоса «Звук не идёт»
с точным указанием, кого не слышно и сколько ждали. Раньше её не было:
пока браузер честно стоял в состоянии «new», не было ни ошибки, ни звука,
и выглядело это как «ничего не происходит».

Подсказка под плиткой участника тоже отвечает прямо: «связь не
устанавливается», «громкость на нуле», «звук у вас выключен».

### Проверка по одному нажатию

Настройки → «Проверить звук». Три шага, три ответа без терминов:

| Шаг | Что покажет |
|---|---|
| колонки | короткий тон — слышно ли что-нибудь вообще |
| микрофон | меряет две секунды: слышит ли он вас |
| | и отдельно — что реально **уходит в сеть** |
| кнопка «Микрофон» | горит только когда дорожка правда звучит |
| связь | с каждым в канале: соединена ли и идут ли байты |

По ответам сразу видно, где обрыв: тон не слышен — дело в колонках;
микрофон молчит — в нём самом; связь не устанавливается — в брандмауэре.

В консоли браузера доступно подробнее:

```js
await netspeak.voice.linkReport(idУчастника)
```

Она покажет состояние соединения, обмен адресами и **сколько байт звука
реально пришло** — по нему сразу видно, доходит ли звук вообще.

## База на сервере

Сервер помнит всех, кто к нему заходил: `uid`, имя, аватар. И переписку
хранит там же. Всё в одном файле `data/netspeak.db` — SQLite, он уже
встроен в Python, ставить ничего не нужно и отдельный сервер поднимать
не нужно.

### Про «и данные есть в базе, и локально»

Не конфликтует, потому что это разные вещи:

| Где | Что | Чья это правда |
|---|---|---|
| `user/profile.json` рядом с exe | мой профиль на этом компьютере | моя |
| таблица `users` в базе | список всех, кто бывал на сервере | сервера |
| таблица `messages` в базе | переписка | сервера |

Правило одно и потому предсказуемое: **свою строку человек
перезаписывает сам, чужие строки не трогает никто.** Зашёл — сервер
обновил твою строку тем, что ты прислал. Увидел чужого — прочитал из
базы и показал. Спора быть не может: автор строки один, и это человек.

Отсюда то, чего раньше не было: **аватар собеседника виден**, даже если
человек сейчас не в сети, а вчерашние сообщения показывают его, а не
кружок с буквой.

### Аватар всегда из базы

Аватар не приходит от клиента. Клиент присылает только свой номер человека,
а сервер берёт картинку из таблицы `users` — и при входе, и при смене
профиля. Так нечему расходиться: одна правда, один источник.

Раньше клиент присылал ссылку вида `/avatars/имя.png`, а сервер ждал имя
файла и молча отбрасывал всё с косой чертой. Картинка не доходила ни при
входе, ни при смене аватара.

В ссылке есть номер версии: `/avatars/имя.png?v=3`. Он растёт при каждой
загрузке картинки. Файл называется по постоянному номеру человека и
перезаписывается на месте, поэтому без номера адрес не менялся бы — браузер
показывал бы прежнюю картинку, пока страницу не перезагрузишь вручную.
Именно на это похожи «проблемы с отображением»: у одного человека аватар
появлялся, у другого оставался старый.

Аватары лежат в `user/avatars/` и называются по uid — `2f9c....png`.
Имя выводится из идентификатора человека, а не выбирается клиентом:
раньше двое могли назвать картинку одинаково, и один аватар молча
затирал другой.

### Что в базе

**`users`** — `uid`, `name`, `avatar`, `show_circle`, `color`,
`first_seen`, `last_seen`, `visits`.

**`messages`** — время, канал, вид (сообщение / личное / файл / система),
uid автора, id соединения, имя, цвет, текст или файл.

Держим 2000 сообщений на канал, старые подрезаются при запуске.
Посмотреть можно обычной программой для SQLite — например, DB Browser
for SQLite.

### Почему выбор микрофона не хранится на сервере

Настройки приложения общие для всех, кто подключился. Но номер микрофона
привязан к компьютеру: на ноутбуке и на настольном он разный, и сохранённый
на одном на другом не существует.

Раньше выбор микрофона уезжал на сервер, и выходило неприятно: человек
подключался с другого компьютера, браузер отказывался открывать несуществующее
устройство — и в сеть уходила тишина. При этом всё выглядело исправно:
человек в сети, кнопка «Микрофон вкл», а его не слышно.

Теперь выбор микрофона и динамиков хранится **в браузере этого компьютера**,
а всё остальное — по-прежнему на сервере. Плюс, если устройство всё же
прописано, но его нет, программа берёт микрофон по умолчанию и говорит об
этом вслух.

### Почему оба файла в одной папке — это нормально

Так и задумано, и конфликтов нет. На диск пишет только сервер: клиент
NetSpeak.exe лишь открывает окно, указывающее на сервер, и сам ничего на диск
не сохраняет. Порты тоже не пересекаются — сервер занимает 8765 и 8766,
клиент к ним подключается.

### Старые файлы переписки

При первом запуске с базой файлы из `history/` переносятся в неё целиком
и больше не нужны. **Файлы не удаляются** — на случай отката. Повторный
перенос ничего не дублирует.

### Что в чём

**`user/profile.json`** — кто вы. Переносится между компьютерами.

| Поле | Смысл |
|---|---|
| `name` | имя |
| `avatar` | имя файла картинки в `user/avatars/` |
| `showCircle` | показывать цветной кружок с буквой, если картинки нет |

**`settings/app.json`** — как программа работает на этом компьютере.

| Поле | Смысл |
|---|---|
| `theme` | `dark` / `light` |
| `mode` | `ptt` (удержанием) или `on` (всегда) |
| `key` | клавиша разговора в режиме удержания |
| `hotkey` | клавиша включения микрофона в режиме «Всегда» |
| `mic`, `speaker` | микрофон и наушники по умолчанию |
| `gain`, `highpass`, `gate`, `leveling` | обработка звука |
| `echo`, `noise`, `agc` | что доверить браузеру |
| `lastServer` | адрес и порт последнего сервера |
| `defaultPort` | порт по умолчанию |

Оба файла — обычный JSON, их можно править руками в блокноте. Запись
атомарная: при сбое питания файл не остаётся наполовину записанным.

## Обновления

Обе программы сами смотрят за новыми версиями на GitHub. Смотрят по
релизам, и у сервера и клиента релизы **разные**: тег `client-v1.1.0`
про клиента, `server-v1.1.0` про сервер. Обновление клиента никогда не
трогает сервер.

**Клиент** проверяет при каждом запуске. Нашёл новую версию — скачивает
и пишет в журнал; при следующем запуске подменяет себя сам. Нажимать
ничего не нужно.

**Сервер** смотрит раз в сутки. Нашёл — скачивает сразу, не дожидаясь
ночи, и показывает в окне:

> Обновление 1.0.0 → 1.1.0 скачано. Сервер сам перезапустится с ним
> в 3:00 ночи — или нажмите «Перезапустить».

В 3:00 ночи сервер перезапускается уже на новой версии. Разговор в это
время прервётся. Нажали «Перезапустить» раньше — обновление встанет сразу.

Интернет для работы программы не нужен, только для проверки обновлений.
Без сети всё работает как прежде, просто новостей не будет.

Настройки, профиль и переписка при обновлении не страдают: они лежат в
`user/`, `settings/` и `history/` рядом с exe и при подмене не трогаются.

Как выпустить релиз — в [docs/релиз.md](docs/релиз.md).

## Окно приложения

Приложение живёт в собственном окне на WebView2 — движок из Microsoft Edge,
он уже есть в Windows 11. Отдельная установка не нужна.

- **«_»** — свернуть в трей. Окно пропадает, значок остаётся у часов.
- **«x»** — спросит «Вы уверены, что хотите закрыть?» с кнопками **Да** и **Нет**.
- В трее: показать окно, открыть в браузере, выход.

Браузер тоже доступен — так удобнее с телефона.

Окно приложения всегда открывает адрес `127.0.0.1`. Браузер считает его
защищённым контекстом, поэтому микрофон работает, а предупреждения о
самоподписанном сертификате не появляется вовсе. Остальным участникам сети
адрес выдаётся по HTTPS — им предупреждение будет, это безопасно.

## Микрофон

Два режима, переключаются в настройках:

- **Всегда** (по умолчанию) — микрофон работает постоянно, выключается
  сочетанием клавиш. По умолчанию **Правый Ctrl + Ins**: левый Ctrl часто
  занят в играх, а этот — нет.
- **Удержанием** — микрофон включается, пока держите выбранную клавишу
  (по умолчанию Пробел).

Клавиши назначаются прямо в настройках: нажмите на поле и нажмите нужное
сочетание. Раскладка клавиатуры значения не имеет.

Если Пробел не включает микрофон, когда вы печатаете сообщение — так и
задумано: пока вы в поле ввода, программа не вмешивается.

Под ползунком громкости — индикатор. Зелёная часть уйдёт в сеть, красная
срежется «Порогом шума».

## Сборка

Нужен Python и три пакета — **только для сборки**, в готовых exe всё внутри:

```bash
python -m pip install pyinstaller pywebview pystray pillow
python build.py
```

Получится два файла в `bin/`. Сборка использует `src/netspeak.spec`: точка
входа и имя файла приходят через переменные окружения, поэтому из одного
описания собираются обе программы.

Папка `web/` рядом с exe **перекрывает** встроенную — чтобы поправить
вёрстку или скрипт, не нужно пересобирать.

### Значки

Рисуются из того же знака, что логотип в интерфейсе. У клиента он
зелёно-синий, у сервера — бордовый, чтобы окна не путались в панели задач
и в трее.

```bash
python tools/make_icon.py            # оба
python tools/make_icon.py --server   # только серверный
```

Получится `src/web/icon.ico` и `src/web/icon-server.ico`. Сборка сама
подставляет нужный каждой программе.

### Перенос в репозиторий

```bash
python publish.py
```

Копирует в репозиторий только исходники — рабочие папки (`settings/`,
`user/`, `logs/`, `data/`, `history/`) и собранные `bin/` остаются позади.
Куда копировать — в самом скрипте, первая константа.

### Почему WebView2, а не Tkinter

Pywebview требует главный поток, и Tkinter требует главный поток. В одном
процессе оба работать не станут, поэтому окна на WebView2.

### Почему HTTPS

Браузер даёт доступ к микрофону только в защищённом контексте. По обычному
HTTP из локальной сети функции `getUserMedia` просто нет — голос бы не работал.
Поэтому сервер выпускает самоподписанный сертификат при первом запуске
(нужен `openssl`: в Windows он идёт в составе Git for Windows) и поднимается
на 8766, а обычный порт перенаправляет на него.

### Почему 8 человек

Голос идёт «каждый с каждым»: у четырёх участников одновременно звучат
12 потоков, у восьми — 56. Дальше связь начинает заикаться на слабых
машинах, поэтому 8 — это разумный предел.

## Отладка

### Ключи командной строки

| Ключ | Что делает |
|---|---|
| `NetSpeakServer.exe --serve --tls-port N --port M` | сервер без окна |
| `NetSpeak.exe --diag` | проверить, что файлы интерфейса на месте |

### Переменные окружения

| Переменная | Значение |
|---|---|
| `NETSPEAK_PORT` | обычный порт |
| `NETSPEAK_TLS_PORT` | защищённый порт, по умолчанию 8766 |
| `NETSPEAK_NO_TLS` | `1` — без HTTPS, только для отладки |
| `NETSPEAK_MAX_USERS` | сколько человек в канале |
| `NETSPEAK_PASSWORD` | пароль входа на сервер |
| `NETSPEAK_NAME` | название сервера |
| `NETSPEAK_OPEN_BROWSER` | `1` — открыть браузер при старте сервера; по умолчанию не открывается |
| `NETSPEAK_UPDATE_API` | адрес API GitHub; нужно для проверки обновлений |
| `NETSPEAK_NO_UPDATE` | `1` — не проверять обновления вовсе |

### Из исходников

```bash
python src/server.py --tls-port 8766 --port 8765   # только сервер
python src/serverapp.py                            # сервер с окном
python src/launcher.py                             # клиент
```

Для окон нужен `pywebview`, `pystray` и `pillow`.

В консоли браузера доступно `window.netspeak` — там `state` и `voice`.
