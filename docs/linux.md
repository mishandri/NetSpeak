# Сборка под Linux

Рабочий код под Linux написан, но ещё ни разу не запущен. Здесь — что
сделано, что осталось и как пользоваться результатом.

**Инструкция для пользователя Ubuntu — в [ubuntu.md](ubuntu.md).**

---

## Коротко о том, как это собирается

Сборка уезжает на серверы GitHub по тегу. Своя машина для этого не
нужна ни в чём: ни Linux на ней, ни Docker, ни WSL.

1. Включите Actions: **Settings → Actions → General → «Allow all actions
   and reusable workflows»**.
2. Пушите тег `client-v1.0.4` или `server-v1.0.4`.
3. GitHub собирает оба бинарника и кладёт их в релиз этого тега.

Ручной запуск: **Actions → Сборка Linux → Run workflow**. Так удобно
проверить, что сборка жива, не выпуская релиз.

## Сделано

### Код работает на обеих системах

Одна программа на Windows и Linux. Правило, по которому всё писалось:
поведение на Windows не меняется ни на байт, всё новое живёт за
проверками `os.name`.

| Что | Было | Стало |
|---|---|---|
| Номер компьютера | реестр Windows | реестр + `/etc/machine-id` |
| Адреса сети | `ipconfig` | `ipconfig` или `ip -4 addr` |
| Имя файла сервера | `NetSpeakServer.exe` | с расширением на Windows, без на Linux |
| Брандмауэр | `netsh` | на других системах честно говорит «только для Windows», кнопка в окне прячется |
| Значок в трее | `.ico` | тот же `.ico` — PIL открывает его где угодно |
| Подтверждение закрытия | pythonnet | без него просто закрывается |

Вывод `ip -4 addr` переписывается в вид ipconfig, чтобы разбор адресов
был один на обеих системах. Иначе в коде оказалось бы две копии правил
разбора, и они разошлись бы со временем.

### Сборка

- `build_linux.py` — по образцу `build.py` для Windows: тот же порядок,
  те же имена, та же версия из исходников. Различия вынужденные: файлы
  без расширения, нет описания версии для свойств файла, рядом
  кладётся `.desktop` и ставится право на запуск.
- `src/netspeak-linux.spec` — без значка и версии (их в Linux нет), без
  pythonnet.
- `requirements-linux.txt` — зависимости с закреплёнными версиями.
- `.github/workflows/release-linux.yml` — сборка по тегу.

`docs/ubuntu.md` — инструкция для Ubuntu: что поставить, как запустить,
что делать с брандмауэром и микрофоном, и что делать, если окно не
появилось.

Все 18 проверок проходят. Отдельно — что номер компьютера на Windows не
сдвинулся: иначе все люди сразу стали бы новыми и потеряли имена с

## Как собрать у себя на Ubuntu

Собирать надо **системным Python**, иначе мост между Python и GTK
останется не там, где его ищет сборка. Проверено на себе: бинарник,
собранный обычным venv, падал при запуске с

```
ModuleNotFoundError: No module named 'gi'
```

и выглядело это так: папки создались — и ничего не произошло.

```bash
# 1. Мост и окно. Имена webkit различаются между 22.04 и 24.04, а
#    чужого имени apt не знает: попросишь оба — установка свалится
#    целиком. Поэтому каждая версия ставится отдельно, и не нашедшаяся
#    просто пропускается.
sudo apt-get update
sudo apt-get install -y \
  python3-pip python3-gi python3-gi-cairo gir1.2-gtk-3.0 libgtk-3-0 patchelf
sudo apt-get install -y gir1.2-webkit2-4.0 gir1.2-soup-2.4 \
  libwebkit2gtk-4.0-37 || true
sudo apt-get install -y gir1.2-webkit2-4.1 gir1.2-soup-3.0 \
  libwebkit2gtk-4.1-0 || true
# значок в трее — по желанию: без него программа работает как обычно
sudo apt-get install -y gir1.2-ayatanaappindicator3-1 || true

# 2. Проверить, что мост на месте. Не напечаталась версия — пакета нет.
python3 -c "import gi; gi.require_version('Gtk','3.0'); print(gi.__version__)"

# 3. Исходники
git clone -b linux https://github.com/mishandri/NetSpeak.git
cd NetSpeak

# 4. Окружение С доступом к системным пакетам. Простое venv не подойдёт:
#    gi лежит в /usr/lib/python3/dist-packages и в него не попадёт.
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
pip install -r requirements-linux.txt

# 5. Собрать
python build_linux.py
```

### Что сделано, чтобы это не повторилось

- `build_linux.py` проверяет `gi` **до** сборки и, если его нет,
  объясняет, что ставить и почему через `pip` не выйдет. Раньше
  проверок не было, и сборка «успешно» проходила, выдавая файл,
  падающий при запуске.
- `src/netspeak-linux.spec` говорит PyInstaller искать `gi` в
  `/usr/lib/python3/dist-packages` и явно перечисляет `gi.repository.*`.
- Файл сборки на серверах GitHub больше не ставит Python из своего
  запаса: именно из-за этого `gi` и не попадал внутрь.

### Чего сборка не может

Полностью переносимого файла на Linux не выйдет. Внутрь уезжает всё
приложение и сам Python, но настоящий оконный движок — GTK, WebKit2 и
мост к ним — остаётся в системе. Причина не в NetSpeak, а в Linux:
подсистема окон — часть операционной системы, и это так у всех
программ с окнами, а не только у этой.

Отдельно: файл, собранный на Ubuntu 22.04, требует не более старой
glibc, чем там. Собранный на 24.04 на 22.04 не запустится.

## Осталось

### 1. Собрать и запустить вживую

Главное. Под Windows окно рисует WebView2, под Linux — GTK через
WebKit2. Это разные движки, и микрофон с разрешениями могут вести себя
иначе. Проверять руками, по порядку важности:

1. микрофон — слышно ли себя в «Проверить связь»;
2. звук — слышно ли собеседника;
3. имя и аватар — сохраняются ли после перезапуска;
4. сообщения в чате — доходят ли.

Автотестами это не проверить: они и на Windows звук не проверяют.

### 2. Обновление под Linux

Сейчас не работает молча и безопасно: файлы в релизе называются без
`.exe`, а обновлялка ищет именно `.exe`, поэтому обновление просто не
находится — и это лучше, чем скачать не то и не поставить.

Доделывать или нет — отдельное решение. Причина, по которой пока не
сделано, честная и неприятная: программа на Linux это файл в папке, а не
запись в реестре. «Подменить» его можно только распаковав архив поверх
старого, а это надо делать в фоне и аккуратно — куча способов сделать
неправильно.

### 3. Значок в системном меню

`.desktop` кладётся в папку сборки и человек копирует его сам. Автоматической
установки нет: программа переносная и ничего в системе менять не должна.

## Чего по-прежнему не хватает на этой машине

| Чего | Есть | Значит |
|---|---|---|
| Linux (WSL) | движок есть, дистрибутива нет | PyInstaller не умеет собирать Linux из Windows |
| Docker / Podman | нет | второй способ запустить Linux, тоже нет |
| Виртуализация | есть | WSL поставить можно, но незачем |
| `gh` (GitHub CLI) | нет | и не нужен: файлы в репозиторий попадают через `git push` |

Виртуализация включена, система — Windows 11 Pro. WSL поставится через
`wsl --install -d Ubuntu` с правами администратора и перезагрузкой.

**Но ставить WSL ради сборки не стоит.** Он нужен, чтобы *запустить*
собранное: без работающей Ubuntu под рукой живой разговор не проверить.
Если под рукой есть виртуальная машина с Ubuntu, этого достаточно, и WSL
не нужен вовсе.
