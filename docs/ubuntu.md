# NetSpeak на Ubuntu

Коротко: скачать, распаковать, сделать два файла запускаемыми, запустить
сервер. Дальше — обычный разговор.

---

## Что нужно до первого запуска

Сама программа — один файл. Python и все пакеты внутри: ни `pip`, ни
виртуального окружения ставить не нужно.

Но окно на Linux рисует GTK, и для этого нужен **мост между Python и
GTK** — модуль `gi`. Он не ставится через `pip`: это C-расширение,
собранное системой под конкретную версию Python. Приходит он одним из
пакетов apt и внутри бинарника сам по себе не появляется.

Если его нет, программа запускается, создаёт папки — и не показывает
ничего. В журнале это выглядит так:

```
ModuleNotFoundError: No module named 'gi'
```

Один раз ставим:

```bash
sudo apt-get update
sudo apt-get install -y python3-gi python3-gi-cairo gir1.2-gtk-3.0
```

И проверяем, что мост на месте:

```bash
python3 -c "import gi; gi.require_version('Gtk','3.0'); print(gi.__version__)"
```

Напечаталась версия — мост есть. Сказало `ModuleNotFoundError` — пакета
`python3-gi` нет.

Дальше нужен WebKit2 — движок, который показывает страницу. На Ubuntu
24.04 ставится один пакет:

```bash
sudo apt-get install libwebkit2gtk-4.1-0
```

На Ubuntu 22.04 он называется `lib-webkit2gtk-4.0-37`. Какой у вас —
покажет:

```bash
lsb_release -a
```

Если ставите значок в трее — ещё один пакет. Без него программа
работает, но закрывать окно придётся завершая процесс:

```bash
sudo apt-get install libayatana-appindicator3-1
```

Полным списком, с проверкой:

```bash
sudo apt-get update
sudo apt-get install -y python3-gi python3-gi-cairo gir1.2-gtk-3.0 \
                        libwebkit2gtk-4.1-0 libayatana-appindicator3-1
dpkg -l libgtk-3-0 | grep '^ii'
```

## Как запустить

### 1. Положить файлы в одну папку

Два файла: `NetSpeakServer` и `NetSpeak`. Расширения у них нет — так
собрано специально, в Linux расширения не полагаются.

### 2. Разрешить запуск

```bash
cd путь/к/папке
chmod +x NetSpeakServer NetSpeak
```

Без этого будет `Permission denied`. Право на запуск слетает при каждом
копировании и при каждой перезагрузке, поэтому эту строку придётся
повторять — это особенность Linux, а не NetSpeak.

### 3. Запустить сервер

```bash
./NetSpeakServer
```

Появится окно сервера. В журнале будет написано, по какому адресу к
нему подключаться, — что-то вроде `192.168.1.5:8766`. Этот адрес и есть
то, что нужно вводить клиентам.

### 4. Подключить клиентов

На любом компьютере в той же сети:

```bash
./NetSpeak          # свой компьютер
```

или на чужом — указать адрес сервера. Если открывать в браузере (телефон,
чужой ноутбук), то в адресной строке `https://192.168.1.5:8766`, и
предупреждение о сертификате придётся пропустить один раз: браузер
открывает адрес сам, мимо программы.

## Папка программы

При первом запуске рядом с файлами появляются рабочие папки — ровно как
в Windows:

| Папка | Что внутри |
|---|---|
| `settings/` | настройки сервера |
| `user/` | имя, аватар, `device.json` |
| `logs/` | `launcher.log` и `server.log` — сюда смотреть, если что-то не так |
| `data/` | база, сертификат, файлы, переданные в чате |
| `history/` | переписка по каналам |

Перенести программу на другой компьютер — просто скопировать папку целиком.

## Сервер без окна

Окно удобно: видно журнал и состояние. Но на машине без рабочего стола —
а сервер вполне может стоять на старом системнике в углу — окно не нужно
и библиотеки для него тоже не нужны.

```bash
./NetSpeakServer --serve
```

В этом режиме программа не открывает окно и не обращается к GTK, поэтому
работает даже там, где графики нет вовсе. Остановить — `Ctrl+C`.

Журнал пишется в двух местах сразу: в `logs/server.log` и, если запущено
из терминала, ещё и в сам терминал. Так что запустил — сразу видишь,
что происходит, а не гадаешь, работает ли.

Когда сервер запускается из окна (обычный случай), терминала нет, и
поведение прежнее: всё пишется в файл, а окно его показывает.

Остановить сервер в этом режиме можно и по-другому — командой
`pkill -f NetSpeakServer`. Но `Ctrl+C` честнее: сервер успевает
закрыть базу, и переписка не остаётся в промежуточном состоянии.

## Значок и запуск из меню

Рядом с программой лежат готовые файлы `NetSpeakServer.desktop` и
`NetSpeak.desktop`. Чтобы они появились в меню приложений:

```bash
mkdir -p ~/.local/share/applications
cp NetSpeakServer.desktop NetSpeak.desktop ~/.local/share/applications/
chmod +x ~/.local/share/applications/NetSpeak*.desktop
```

Значок в меню возьмётся из `icon.png`, который рядом с программой: тот же
рисунок, что и на Windows, но в том виде, в каком его умеет показывать
Linux. В Windows значок живёт прямо в exe, здесь — отдельным файлом, так
устроен Linux.

В `Exec` прописан **полный путь**. Если перенести папку в другое место,
править надо там же: откройте файл текстовым редактором и замените путь.

## Звук и брандмауэр

Голос идёт напрямую между компьютерами и сервера не касается. Поэтому
брандмауэр на машине **сервера** должен пускать входящие UDP-соединения.
По умолчанию `ufw` их не пускает, и выглядит это так: все на месте, все
друг друга видят, а звука нет. Самая неприятная ошибка, потому что ничто
не выглядит сломанным.

Проверить:

```bash
sudo ufw status
```

Если `Status: active`, разрешить:

```bash
sudo ufw allow 8766/udp      # голос между участниками
sudo ufw allow 8766/tcp      # раздача приложения и переписки
```

Кнопки «Разрешить в брандмауэре» в окне сервера на Linux нет: там стоял бы
`netsh`, которого в Linux не бывает, а `ufw` требует `sudo` из окна
программы. Это сделано намеренно — программа не должна молча просить у вас
права администратора.

Если всё равно не слышно, в окне приложения нажмите **«Проверить связь»**:
по шагам видно, где обрыв — колонки, микрофон или связь с собеседником.

---

## Микрофон

Браузер спросит разрешение на микрофон при первом входе — это нормально,
и нужно ответить «разрешить». Отказались случайно:

```bash
# Firefox
about:permissions → микрофон → «Очистить» → перезапустить страницу
# Chrome
chrome://settings/content/microphone → «Удалить» для этого адреса
```

## Если окно не появилось

Самая частая причина — не хватает тех самых библиотек из начала.
Проверить:

```bash
ldd ./NetSpeak | grep -i 'not found'
```

Если что-то `not found` — поставьте недостающее и запустите снова.

---

## Если `Permission denied`

Право на запуск слетело. Достаточно одного `chmod +x`.

## Обновление

Пока автоматического обновления под Linux нет. Причина честная и
неприятная: программа на Linux — это файл в папке, а не запись в
реестре, и «подменить» его можно только распаковав новый архив поверх
старого. Автоматически это означало бы распаковывать архив в фоне и
подменять работающий файл — куча способов сделать это неправильно и
сломать человеку программу.

Поэтому: скачать новую версию, распаковать поверх, сделать `chmod +x`.
Папки `settings/`, `user/`, `logs/`, `data/` и `history/` при этом
остаются на месте — пропадёт только сама программа, если распаковать
аккуратно.

Отдельно: сервер на Windows никогда не скачивает обновление клиента и не
может его кому-то выдать. Обновление приходит с GitHub напрямую, и только
на ту машину, где он установлен.

---

## Что пока не проверено

Честно о границах. Под Windows программа проверена и работает; под Linux
собрана, но ещё ни разу не запущена в живом разговоре. Окно на Linux рисует
GTK через WebKit2, а на Windows — WebView2. Это разные движки, и микрофон
с разрешениями могут повести себя иначе.

Поэтому проверять вживую нужно в первую очередь вот это:

1. микрофон — слышно ли себя в «Проверить связь»;
2. звук — слышно ли собеседника;
3. имя и аватар — сохраняются ли после перезапуска;
4. сообщения в чате — доходят ли.
