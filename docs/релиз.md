# Как делать релиз

Сервер и клиент — **разные программы и разные релизы**. Общего релиза нет
намеренно: обновление клиента никогда не должно трогать сервер.

| Что | Тег релиза | Файл в релизе |
|---|---|---|
| Клиент | `client-v1.0.0` | `NetSpeak-1.0.0.exe` |
| Сервер | `server-v1.0.0` | `NetSpeakServer-1.0.0.exe` |

Программа ищет релиз с нужным префиксом тега и берёт из него файл `.exe`.
Всё остальное — имя тега, описание, остальные вложения — ей безразлично.

---

## Порядок

### 1. Поднять версию

В `src/netspeak/__init__.py` одна строка:

```python
__version__ = "1.1.0"      # была 1.0.0
```

Версия растёт по-обычному: 1.0.1 — починка, 1.1.0 — новое, 2.0.0 — несовместимое.

### 2. Собрать

```bash
python -m pip install pyinstaller pywebview pystray pillow
python build.py
```

В `bin/` появятся `NetSpeak.exe` и `NetSpeakServer.exe`. Проверьте, что
оба запускаются из чистой папки и оба открывают окна.

> Собирать нужно на той же Windows, для которой делаете релиз. PyInstaller
> не умеет собирать Windows-файл из Linux и наоборот.

### 3. Перенести в репозиторий

```bash
python publish.py
```

Скрипт скопирует в репозиторий только исходники: рабочие папки
(`settings/`, `user/`, `logs/`, `data/`, `history/`) и собранные `bin/`
в репозиторий не попадут.

### 4. Закоммитить и выгрузить

```bash
cd D:\Documents\Git\NetSpeak
git add -A
git commit -m "NetSpeak 1.1.0"
git push
```

### 5. Создать релиз на GitHub

Откройте <https://github.com/mishandri/NetSpeak/releases/new>.

**Клиент:**
- Имя тега: `client-v1.1.0`
- Название: `NetSpeak 1.1.0`
- Прикрепить: `bin\NetSpeak.exe`

**Сервер:**
- Имя тега: `server-v1.1.0`
- Название: `NetSpeakServer 1.1.0`
- Прикрепить: `bin\NetSpeakServer.exe`

Описание релиза пишется по-русски и коротко: что изменилось и что
теперь надо сделать пользователю.

> Если релиз правится после публикации, версию поднимать не надо:
> дописывайте в тот же тег, программа всё равно скачает файл заново.

## Что происходит у пользователя

### Клиент

1. При каждом запуске спрашивает GitHub: есть ли `client-vX.Y.Z` новее той,
   что запущена.
2. Нашёл — скачивает в папку `update/` и пишет в `logs/launcher.log`:
   `обновление скачано, программа обновится при следующем запуске`.
3. При следующем запуске подменяет сама себя и открывается заново.

Ничего нажимать не нужно. Переписка, настройки и профиль не страдают:
они лежат в `user/` и `settings/` рядом с exe и при подмене не трогаются.

### Сервер

1. Раз в сутки смотрит за релизом `server-vX.Y.Z`.
2. Нашёл — скачивает **сразу**, не дожидаясь ночи.
3. В окне сервера появляется строка
   «Обновление 1.0.0 → 1.1.0 скачано. Сервер сам перезапустится с ним
   в 3:00 ночи — или нажмите „Перезапустить“».
4. В 3:00 ночи сервер перезапускается уже на новой версии. Разговор в
   это время прервётся.
5. Если нажали «Перезапустить» раньше — обновление встанет сразу.

Переписка из `history/` при обновлении сохраняется.

## Если что-то пошло не так

**Программа не видит обновление.** Проверьте тег: он должен начинаться с
`client-v` или `server-v` и состоять из цифр через точки — `client-v1.1.0`.
Тег `v1.1.0` или `client-1.1.0` программа проигнорирует.

**В релизе нет файла.** Нужен файл с расширением `.exe`. Без него
программа не знает, что скачивать, и промолчит.

**Интернета нет.** Обновление не требует интернета для работы самой
программы — только для проверки. Без сети программа работает как обычно,
просто не узнает о новых версиях.

**Не установлено.** Посмотрите `logs/launcher.log`: туда пишется всё —
что нашлось, что скачалось, что сломалось. Файл в блокноте открывается.

**Откат.** Верните в `src/netspeak/__init__.py` прежнюю версию, соберите
и выложите под **новым** тегом: `client-v1.1.1`. Понижение версии
программа не делает — она никогда не ставит «более старую» сборку.

## Про Linux

Сборки под Linux на моей машине не получается: нет ни WSL, ни Docker, а
PyInstaller не умеет собирать Linux из Windows.

Да и мне это пока что не нужно =)

Когда понадобится — самый простой путь: файл `.github/workflows/release.yml`,
который при пуше тегов `client-v*` и `server-v*` собирает бинарники на
серверах GitHub. Организация работы та же: тег → сборка → релиз.
